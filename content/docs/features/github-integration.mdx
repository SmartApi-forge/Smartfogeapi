# GitHub Integration

SmartAPIForge integrates seamlessly with GitHub to provide version control, team collaboration, and automated deployment workflows.

## Key Features

- Push and pull changes between sandbox and GitHub
- Create, switch, and merge branches
- Generate repositories directly from projects
- Real-time collaboration with team members
- Trigger CI/CD pipelines on push
- Pull request creation and management
- Branch protection and code reviews

## Overview

The GitHub integration allows you to:

- 🔄 **Sync Code** - Push and pull changes between sandbox and GitHub
- 🌿 **Manage Branches** - Create, switch, and merge branches
- 📦 **Create Repositories** - Generate repos directly from projects
- 👥 **Collaborate** - Work with team members on shared codebases
- 🚀 **Automate** - Trigger CI/CD pipelines on push

<Callout type="info" title="OAuth Authentication">
  SmartAPIForge uses GitHub OAuth for secure, token-based authentication. Your credentials are never stored.
</Callout>

## Getting Started

### Connect Your GitHub Account

First-time setup:

1. Click the **GitHub** icon in the project header
2. Click **Connect GitHub Account**
3. Authorize SmartAPIForge on GitHub
4. Grant repository access permissions

<Callout type="success" title="Connected">
  Your GitHub account is now connected! You can now create repositories and sync code.
</Callout>

### Required Permissions

SmartAPIForge requests the following GitHub permissions:

| Permission | Purpose |
|------------|---------|
| **repo** | Create and manage repositories |
| **user:email** | Access your email for commits |
| **read:org** | List organizations you belong to |
| **workflow** | Trigger GitHub Actions (optional) |

<Callout type="warning" title="Privacy">
  SmartAPIForge only accesses repositories you explicitly connect. We never read or modify other repositories.
</Callout>

## Creating Repositories

### From a New Project

When generating a new API:

1. Generate your API code
2. Click **GitHub** icon
3. Click **Create Repository**
4. Configure repository settings:
   - **Name:** my-api-project
   - **Description:** Generated by SmartAPIForge
   - **Visibility:** Public or Private
   - **Initialize:** README, .gitignore, LICENSE
5. Click **Create**

The repository is created and your code is pushed automatically.

### From an Existing Project

Convert an existing project to a GitHub repository:

1. Open your project
2. Click **GitHub** icon
3. Click **Create Repository**
4. Choose **Push existing code**
5. Configure and create

<Callout type="info" title="Initial Commit">
  SmartAPIForge creates an initial commit with message: "Initial commit from SmartAPIForge"
</Callout>

## Working with Branches

### Viewing Branches

See all branches in your repository:

1. Click **GitHub** icon
2. View branch dropdown
3. See current branch (highlighted)
4. See all available branches

### Creating Branches

Create a new branch:

1. Click **GitHub** icon
2. Click **+** next to branches
3. Enter branch name:
   ```
   feature/add-authentication
   feature/user-management
   bugfix/fix-validation
   hotfix/security-patch
   ```
4. Click **Create**

<Callout type="success" title="Branch Created">
  The new branch is created on GitHub and your sandbox switches to it automatically.
</Callout>

### Switching Branches

Switch between branches:

1. Click **GitHub** icon
2. Select branch from dropdown
3. Confirm switch
4. Sandbox restarts with new branch code

**What Happens:**
- Current changes are stashed
- Branch is checked out
- Dependencies are reinstalled
- Server restarts
- Preview updates

### Branch Naming Conventions

Follow these conventions for clarity:

```bash
# Features
feature/user-authentication
feature/payment-integration

# Bug fixes
bugfix/fix-login-error
bugfix/correct-validation

# Hotfixes
hotfix/security-vulnerability
hotfix/critical-bug

# Releases
release/v1.0.0
release/v2.0.0-beta

# Development
develop
staging
```

## Syncing Code

### Pushing Changes

Push your sandbox code to GitHub:

1. Make changes in the code editor
2. Click **GitHub** icon
3. Click **Push Changes**
4. Enter commit message:
   ```
   Add user authentication endpoints
   
   - Implement JWT token generation
   - Add login and register endpoints
   - Include password hashing
   ```
5. Click **Push**

<Callout type="info" title="Commit Messages">
  Write clear, descriptive commit messages following the [Conventional Commits](https://www.conventionalcommits.org/) format.
</Callout>

### Pulling Changes

Pull latest changes from GitHub:

1. Click **GitHub** icon
2. Click **Pull Changes**
3. Confirm pull
4. Sandbox restarts automatically
5. Changes appear in editor

**Conflict Resolution:**

If there are conflicts:

1. SmartAPIForge shows conflict markers
2. Edit files to resolve conflicts
3. Save changes
4. Push resolved code

### Auto-Sync

Enable automatic syncing (optional):

1. Go to **Project Settings**
2. Enable **Auto-sync with GitHub**
3. Choose sync interval:
   - Every 5 minutes
   - Every 15 minutes
   - Every hour

<Callout type="warning" title="Auto-Sync Caution">
  Auto-sync can overwrite local changes. Use with caution in active development.
</Callout>

## Cloning Repositories

### Clone Existing Repository

Import code from an existing GitHub repository:

1. Click **New Project**
2. Select **Clone from GitHub**
3. Choose repository from list
4. Or enter repository URL:
   ```
   https://github.com/username/repo-name
   ```
5. Select branch (default: main)
6. Click **Clone**

SmartAPIForge will:
- Clone the repository
- Create a sandbox
- Install dependencies
- Start the server
- Open the preview

### Supported Repository Types

SmartAPIForge can clone:

✅ **FastAPI Projects**
- Python 3.8+
- requirements.txt or pyproject.toml
- Standard FastAPI structure

✅ **Express.js Projects**
- Node.js 18+
- package.json
- Standard Express structure

✅ **Next.js Projects**
- Next.js 13+
- App Router or Pages Router
- TypeScript or JavaScript

❌ **Not Supported:**
- Monorepos (coming soon)
- Non-web projects
- Projects without package manifests

## Collaboration

### Inviting Team Members

Share your project with team members:

1. Go to **Project Settings**
2. Click **Collaborators**
3. Enter GitHub username or email
4. Choose permission level:
   - **Read:** View code only
   - **Write:** Edit and push code
   - **Admin:** Full project access
5. Click **Invite**

### Working Together

Team collaboration features:

- **Real-time Presence:** See who's online
- **Code Comments:** Comment on specific lines
- **Change Notifications:** Get notified of pushes
- **Branch Protection:** Require reviews before merge

<Callout type="info" title="Team Plan">
  Advanced collaboration features require a Team plan. See [Pricing](/pricing) for details.
</Callout>

### Pull Requests

Create pull requests from SmartAPIForge:

1. Push your changes to a feature branch
2. Click **GitHub** icon
3. Click **Create Pull Request**
4. Fill in PR details:
   - **Title:** Add user authentication
   - **Description:** Implements JWT-based auth
   - **Reviewers:** Select team members
   - **Labels:** enhancement, security
5. Click **Create PR**

The PR opens on GitHub for review and discussion.

## GitHub Actions Integration

### Automatic CI/CD

SmartAPIForge can trigger GitHub Actions workflows:

```yaml
# .github/workflows/deploy.yml
name: Deploy API

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.11'
      
      - name: Install dependencies
        run: pip install -r requirements.txt
      
      - name: Run tests
        run: pytest tests/
      
      - name: Deploy to production
        run: |
          # Your deployment script
          ./deploy.sh
```

## Best Practices

### Commit Frequently

Make small, focused commits:

```bash
# Good commits
✅ "Add user registration endpoint"
✅ "Fix validation error in login"
✅ "Update dependencies to latest versions"

# Bad commits
❌ "Update stuff"
❌ "WIP"
❌ "Fixed things"
```

### Use Branches

Never commit directly to main:

```bash
# Create feature branch
feature/add-feature

# Make changes
# Commit and push

# Create pull request
# Review and merge
```

### Write Good Commit Messages

Follow this format:

```
<type>(<scope>): <subject>

<body>

<footer>
```

Example:

```
feat(auth): add JWT authentication

Implement JWT-based authentication with:
- Token generation on login
- Token validation middleware
- Refresh token support

Closes #123
```

### Protect Important Branches

Enable branch protection on GitHub:

1. Go to repository settings
2. Click **Branches**
3. Add rule for `main` branch:
   - ✅ Require pull request reviews
   - ✅ Require status checks to pass
   - ✅ Require branches to be up to date
   - ✅ Include administrators

## Troubleshooting

### Authentication Failed

**Problem:** Cannot connect to GitHub

**Solutions:**
1. Revoke and reconnect GitHub OAuth
2. Check GitHub service status
3. Verify repository permissions
4. Clear browser cache and retry

### Push Rejected

**Problem:** Push fails with "rejected" error

**Solutions:**
1. Pull latest changes first
2. Resolve any conflicts
3. Try pushing again
4. Check branch protection rules

### Clone Failed

**Problem:** Cannot clone repository

**Solutions:**
1. Verify repository exists and is accessible
2. Check repository is public or you have access
3. Ensure repository has supported structure
4. Try cloning via HTTPS URL

### Merge Conflicts

**Problem:** Conflicts when pulling changes

**Solutions:**
1. Identify conflicting files
2. Edit files to resolve conflicts
3. Remove conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`)
4. Save and push resolved code

## Advanced Features

### Git Hooks

Set up pre-commit hooks:

```bash
# .git/hooks/pre-commit
#!/bin/bash

# Run tests before commit
pytest tests/

# Run linter
flake8 .

# Format code
black .
```

### Submodules

Work with Git submodules:

```bash
# Add submodule
git submodule add https://github.com/user/repo

# Update submodules
git submodule update --remote

# Clone with submodules
git clone --recursive https://github.com/user/repo
```

### Git LFS

Use Git Large File Storage for large files:

```bash
# Install Git LFS
git lfs install

# Track large files
git lfs track "*.psd"
git lfs track "*.mp4"

# Commit .gitattributes
git add .gitattributes
git commit -m "Add Git LFS tracking"
```
